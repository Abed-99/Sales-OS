# قاعدة البيانات

## وين كل شي

| الملف | شو فيه |
|---|---|
| `schemas/01_core.sql` | الشركات، المستخدمين، الصفات والصلاحيات، سجل النشاط |
| `schemas/02_catalog.sql` | الأصناف، الزبائن، الموردين وأسعارهم |
| `schemas/03_accounting.sql` | دليل الحسابات، القيود، أسعار الصرف، الفترات المالية |
| `schemas/04_cash.sql` | الصناديق، المصاريف، حركات المصاري |
| `schemas/05_inventory.sql` | المستودعات، المخزون، التحويلات، الجرد |
| `schemas/06_sales.sql` | عروض الأسعار، الطلبيات، التوصيل، فواتير البيع، القبض |
| `schemas/07_purchases.sql` | فواتير الشراء، الاستلام، الدفع للموردين |
| `schemas/08_returns_approvals.sql` | المرتجعات والموافقات |
| `schemas/09_payroll.sql` | الموظفين، الرواتب، السلف |
| `schemas/10_assets_partners.sql` | الأصول الثابتة والشركاء |
| `schemas/11_auto_accounting.sql` | القيود المحاسبية التلقائية |
| `schemas/12_reports.sql` | التقارير ولوحة التحكم |
| `schemas/13_imports.sql` | الاستيراد: الشحنات والكلفة الواصلة |
| `schemas/14_whatsapp.sql` | رسائل واتساب الجاهزة |
| `schemas/15_catalog.sql` | كتالوج البضاعة للتجار (روابط عامة) |

كل ملف مقسوم لنفس الأقسام وبنفس الترتيب: الجداول، الدوال، العروض، المشغّلات، الحماية (RLS)، الصلاحيات.

## كيف تعدّل

1. عدّل الملف المناسب بمجلد `schemas/` (مثلًا ضيف عمود أو صلّح دالة).
2. شغّل:
   ```bash
   npx supabase db diff -f وصف_قصير_للتعديل
   ```
   هاد بيطلّع ملف جديد بمجلد `migrations/` فيه التعديل بس.
3. جرّب محليًا:
   ```bash
   npx supabase db reset
   npx supabase db lint --level error
   npm run test:db
   ```
   `test:db` بيمشي دورة الشغل كاملة (شراء، استلام، بيع، توصيل، قبض دولار وليرة، مرتجعات، إلغاءات،
   رواتب وسلف، أصول، شركاء، إقفال شهر) وبيتأكد إنه المخزون والقيود والأرصدة والتقارير كلها مطابقة.
   بيشتغل بس على Supabase المحلي، وبيرفض يشتغل على الإنتاج.
4. لما يكون كل شي تمام، بترفع على الإنتاج:
   ```bash
   npx supabase db push
   ```

## قواعد مهمة

- **عدّل بس ملفات `schemas/`.** ملفات `migrations/` بتنولّد لحالها، وما بتنعدّل بعد ما تنرفع على الإنتاج.
- **الزائر (`anon`) ما إله أي صلاحية.** كل جدول ودالة جديدة بتاخد صلاحيات المستخدم المسجّل تلقائيًا، والحماية الفعلية من RLS.
- **دالة داخلية؟** إذا عملت دالة ما لازم المستخدم يناديها مباشرة، ضيف بقسم "الصلاحيات" بآخر الملف:
  ```sql
  revoke execute on function public.اسم_الدالة(أنواع_المدخلات) from authenticated;
  ```
- **بيانات ثابتة** (متل قائمة الصلاحيات) ما بتنولّد بـ `db diff`، فبتنكتب بملف migration يدوي.
